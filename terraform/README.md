# Terraform – שיפור תמיכה בזמינות גבוהה (High Availability)

## מטרת השינוי

בוצעה הרחבה של תשתית ה-Terraform הקיימת, במטרה לאפשר התאמה לתרחיש של זמינות גבוהה (HA) ולתמוך בדרישת המטלה להמשכיות פעילות במקרה של כשל ב-Zone בודד.

השינוי מאפשר להפעיל תצורת HA, תוך שמירה על הגדרות ברירת המחדל של סביבת ה-Lab, המיועדות להרצה מצומצמת וחסכונית.

## השינויים שבוצעו

### 1. פריסת GKE במספר Zones

נוסף פרופיל הגדרות לדוגמה המאפשר לפרוס את Node Pool של GKE בשלושה Zones באזור `me-west1`, במקום פריסה ב-Zone יחיד כברירת מחדל.

פריסה זו מאפשרת לפזר את תשתית ה-Nodes בין מספר Zones, כך שניתן יהיה להמשיך להפעיל את עומסי העבודה במקרה של כשל באחד מהם, בכפוף לזמינות קיבולת מספקת ב-Zones הנותרים.

### 2. התאמת מנגנון ה-Autoscaling

בפרופיל ה-HA הוגדרו:
- מינימום של 3 Nodes.
- מקסימום של 6 Nodes בסך הכול.
- מדיניות `BALANCED` לעידוד פיזור ה-Nodes בין ה-Zones בעת הגדלת ה-Node Pool.

הגדרות אלו מאפשרות גמישות בהתאמת קיבולת התשתית לעומסים, תוך תמיכה בפיזור בין ה-Zones.

### 3. הפעלת High Availability עבור Cloud SQL

בפרופיל ה-HA מופעל `Regional HA` עבור Cloud SQL.

הגדרה זו מספקת Primary ו-Standby Instances ב-Zones נפרדים באותו Region, ומאפשרת מעבר אוטומטי ל-Standby במקרה של כשל ב-Zone שבו פועל ה-Primary.

## שמירה על גמישות ועלויות

הגדרות ברירת המחדל של סביבת ה-Lab נשארו ללא שינוי, כדי לאפשר סביבת עבודה מצומצמת וחסכונית.

נוסף קובץ דוגמה בשם `terraform.tfvars.ha.example`, המציג פרופיל הגדרות התומך בתרחיש HA. ניתן להשתמש בו כבסיס להגדרת הסביבה בהתאם לצורכי הפריסה.
## קבצים ששונו
קובץ	מה השתנה
terraform/platform/gke.tf	התאמת הגדרות ה-Node Pool לתמיכה ב-Autoscaling ובפיזור בין Zones.
terraform/platform/terraform.tfvars.ha.example	קובץ הגדרות לדוגמה לפרופיל HA: שלושה Zones, מינימום 3 ומקסימום 6 Nodes והפעלת Cloud SQL HA.

## אופן בדיקת השינוי
פקודות בדיקה פשוטות:
terraform fmt -check -recursive terraform

terraform -chdir=terraform/platform init -backend=false

terraform -chdir=terraform/platform validate


הסבר קצר:
- fmt – בדיקת אחידות העיצוב של קובצי Terraform.
- init – אתחול סביבת Terraform ללא חיבור ל-Backend מרוחק.
- validate – בדיקת תקינות תחבירית ועקביות של הגדרות Terraform.
חשוב: הבדיקות אינן מוכיחות שהפריסה תצליח בפועל, או שקיימים מכסות ומשאבים זמינים ב-GCP.

## הערות

- פריסה בשלושה Zones ופיזור ה-Nodes אינם מבטיחים לבדם זמינות של האפליקציה. נדרשים גם פיזור Pods בין ה-Zones, הגדרות Kubernetes מתאימות ותכנון קיבולת מספקת.
- מדיניות `BALANCED` מעודדת פיזור בעת הגדלה, אך אינה מבטיחה חלוקה שווה של ה-Nodes בכל מצב.
- `Regional HA` של Cloud SQL מספק שרידות בתוך אותו Region ואינו מהווה פתרון ל-Disaster Recovery אזורי.
- ערכי הקיבולת והמשאבים בקובץ הדוגמה הם ערכי המחשה, ויש להתאימם לפני פריסה בפועל בהתאם לעומסים, למכסות ולעלויות.
